🌐 Data Communication Concepts & Transmission Pipeline
Client-Server Architecture

End-to-End Transmission Workflow

1. Report Packaging

Rural doctor enters patient clinical data. Frontend computes SHA-256 checksum and generates a unique UUIDv4 Idempotency-Key.

2. TCP/IP Transport

Data leaves edge node via TCP port 5000 / HTTPS. HTTP multipart/form-data carries JSON metadata + PDF attachment over IP packets.

3. Server Acceptance & ACK

Flask REST API checks idempotency cache (rejecting duplicates with 409), stores file securely, verifies SHA-256, and returns a 201 Created with Server ACK Token.

4. Hospital Response

Hospital specialist reviews findings, verifies integrity badge, updates status to Under Review, and transmits clinical directives back to rural clinic.

Core Data Communication Curricular Topics Demonstrated:

Client-Server Model

Clear separation between Edge Clinic client, REST API server, and Hospital Core consumers.

Request-Response & RTT

Round-trip latency tracking in milliseconds for each transmission event.

Server Acknowledgement (ACK)

Delivery confirmation tokens guarantee the client does not mark packets delivered prematurely.

Reliable Transport & Backoff

Exponential backoff retry algorithm (1s, 2s, 4s, 8s) ensures network recovery without congestion.

Duplicate Prevention (Idempotency)

Idempotency-Key header prevents duplicate database records upon network retries.

Packet Analysis via Wireshark

Pre-configured display filters and dissection views ready for packet sniffing on loopback or LAN.
